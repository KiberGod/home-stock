# HomeStock

Система управления домашним складом. Работает полностью в браузере и хранит данные в вашей собственной Google-таблице.
Версия **1.0.0**. Языки интерфейса: украинский, английский, русский.

- Категории → группы → товары, выводятся адаптивной сеткой карточек (ПК и телефон).
- Быстрые `+` / `−` на каждой карточке товара, ручной ввод количества на странице редактирования.
- Перетаскивание (drag & drop) задаёт порядок по умолчанию для категорий, групп и товаров (на сенсорных экранах - долгим нажатием).
- Сортировка А–Я / Я–А и по количеству на складе; поиск без учёта регистра (глобальный, внутри категории, внутри группы) с подсветкой совпадений.
- Список «Все товары» с фильтром по группе.
- Предупреждение при уходе со страницы товара с несохранёнными изменениями.
- Светлая / тёмная тема (или как в системе), настройки хранятся локально на устройстве.

Стек: Vite + React + TypeScript, `@dnd-kit` для перетаскивания, Google Identity Services + Sheets API v4.
Бэкенда нет: приложение обращается к Google напрямую из браузера.

## Структура таблицы

При первом подключении HomeStock создаёт следующие листы (пустая таблица считается валидной):

| Лист         | Столбцы                                                          |
|--------------|------------------------------------------------------------------|
| `Meta`       | `key`, `value` (`app = HomeStock`, `schema = 1`)                 |
| `Categories` | `id`, `name`, `icon`, `position`                                 |
| `Groups`     | `id`, `name`, `categoryId`, `position`                           |
| `Items`      | `id`, `name`, `image`, `quantity`, `note`, `groupId`, `position` |

Суммарное количество в группе, картинка группы (берётся у товара, которого больше всего) и число групп в категории вычисляются на лету и в таблице не хранятся.
Таблица, в которой есть непустые посторонние листы и нет листов HomeStock, считается невалидной.

## Настройка Google Cloud (один раз)

Для записи в таблицу нужен вход в Google-аккаунт, поэтому приложению требуется OAuth **Client ID**.
Client ID - это публичный идентификатор (секретного ключа в этой схеме нет); он работает только с тех адресов, которые вы разрешите.

1. Откройте <https://console.cloud.google.com/> и создайте проект (например, `HomeStock`).
2. **APIs & Services → Library** → включите **Google Sheets API**.
3. **Google Auth Platform → Branding** (экран согласия OAuth): название приложения `HomeStock`, ваш email как контакт поддержки/разработчика. Audience: **External**.
4. **Audience → Test users** → добавьте все Google-аккаунты, которые будут пользоваться приложением (пока приложение в режиме *Testing*, войти могут только они).
5. **Data access** → добавьте scope `https://www.googleapis.com/auth/spreadsheets`.
6. **Clients → Create client** → тип **Web application**. Authorised JavaScript origins:
   - `https://kibergod.github.io`
   - `http://localhost:5173` (только для локальной разработки)

   Redirect URI не нужны. Скопируйте **Client ID**.

Пока приложение в тестовом режиме, при входе Google покажет предупреждение «приложение не проверено» - для личного использования это нормально.

## Локальная разработка

```bash
npm install
cp .env.example .env.local      # .env.local игнорируется git
# впишите Client ID в .env.local: VITE_GOOGLE_CLIENT_ID=...
npm run dev
```

В режиме разработки вместо ссылки можно ввести `demo` - тогда приложение работает на локальных тестовых данных без Google.

## Публикация на GitHub Pages

Репозиторий должен быть **публичным**: на бесплатном тарифе GitHub Pages работает только для публичных репозиториев.

1. В репозитории: **Settings → Secrets and variables → Actions → New repository secret**:
   `VITE_GOOGLE_CLIENT_ID` = ваш Client ID.
2. **Settings → Pages → Source: GitHub Actions**.
3. Сделайте push в `main` - `.github/workflows/deploy.yml` соберёт и опубликует сайт на `https://kibergod.github.io/home-stock/`.

Client ID подставляется при сборке из секрета и никогда не хранится в репозитории.

## Доступ для других пользователей

Каждый пользователь входит своим Google-аккаунтом и подключает свою таблицу - данные полностью раздельные.
Пока приложение в режиме *Testing*, войти могут только аккаунты из списка **Test users** (до 100).
Чтобы пускать всех, нажмите **Google Auth Platform → Audience → Publish app**: при входе останется
предупреждение «приложение не проверено», лимит - 100 пользователей, пока приложение не прошло проверку Google.

## Особенности

- Google выдаёт доступ примерно на час. После этого приложение попросит нажать «Продолжить с Google» (один клик); несохранённые изменения при этом не теряются.
- При одновременной правке с двух устройств сохраняется последняя запись. Чтобы это смягчить, данные перечитываются, когда вы возвращаетесь на вкладку спустя минуту и больше.
- Ручная правка листов в Google Таблицах может нарушить структуру - тогда приложение покажет, что именно не так.
